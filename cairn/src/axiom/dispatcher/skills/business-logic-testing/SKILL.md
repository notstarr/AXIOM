## 什么时候读这个 skill

当你要测试以下场景时：订单流程、支付流程、优惠券、积分商城、用户权限、地址管理、文件上传、验证码、会员体系。它告诉你**测什么**和**什么才算真漏洞**。

## 核心原则

**漏洞 = 攻击者获得了超越其合法权限的东西。**

在自己的账号里，用自己的资源，做正常的操作——无论操作方式多么"非常规"，都不是漏洞。只有当你越过了权限边界、绕过了真实限制、或获得了不该获得的东西时，才是漏洞。

## 订单与支付

### 该测什么

1. **跳过支付步骤**：能否不付款就让订单变成已支付状态？（直接调回调、篡改订单状态参数）
2. **篡改金额**：能否修改商品单价、数量、运费使订单总价为 0 或负数？
3. **篡改商品**：能否用商品 A 的价格买到商品 B？（替换 goods_id 但保持 price 不变）
4. **订单状态机绕过**：能否跳过状态？（created 直接到 shipped，或 cancelled 订单仍能支付）
5. **支付回调伪造/重放**：能否伪造支付回调？能否重放一次成功的回调导致重复扣款？

### 什么不算漏洞

- preCalculate（预算价）和 doCreate（创建订单）各自接受 coupon_no — 预算价只是前端预览，不是安全控制
- 取消订单后优惠券恢复 — 这是正常业务逻辑
- 在 doCreate 阶段更换优惠券 — 用户在结算页本来就可以改用哪张券

### 什么算漏洞

- 0 元下单成功（amount=0 且订单创建成功）
- 取消的订单仍能发起支付（状态机校验缺失）
- 伪造支付回调让订单变成已支付
- qty=-1 导致 amount 为负数

## 优惠券

### 该测什么

1. **跨用户使用**：能否用别人的 coupon_no/instance_num 下单？（需要先拿到别人的券 ID）
2. **并发使用**：同一张券同时用于多个订单，是否都生效？（并发不是串行——串行取消重用是正常的）
3. **面值篡改**：能否修改券的面值参数？（5 元券当 50 元用）
4. **过期券使用**：过期券能否仍下单？
5. **批量领取绕过**：能否突破每人限领 N 张的限制？

### 什么不算漏洞

- 用自己的有效券在自己的订单里获得折扣 — 无论在哪个步骤传入
- 取消订单后券恢复可再次使用 — 正常逻辑
- getCouponAvailableGoods 查到其他 coupon_id 的商品列表 — 这是商品目录，不是用户数据

### 什么算漏洞

- 用别人的 instance_num 下单成功（响应中确认使用了非己方券）
- 同一张券并发用于 2 个订单，2 个都生效且未取消
- 篡改 coupon 的 value/discount 参数使折扣变大

## IDOR / 越权

### 该测什么

1. **水平越权**：用 A 的 token 访问 B 的资源（订单、地址、文件、消息）
2. **垂直越权**：普通用户 token 能否调管理接口？
3. **ID 可预测**：order_no、address_id、file_id 是否可枚举？如果可枚举 + 无归属校验 = IDOR

### 什么不算漏洞

- 用自己上传的 file_id 设为头像 — 自己的文件
- 查看自己的订单详情/地址详情 — 自己的数据
- 接口返回 status:1 但没返回他人数据 — 没有实际泄露

### 什么算漏洞

- 用 A 的 token 查到 B 的订单详情（响应中 uid ≠ A）
- 枚举 address_id 查到他人的手机号/身份证号
- 普通 token 成功调用 admin 接口

### 单账号环境下的测试策略

如果只有一个测试账号，无法直接证明"访问了别人的资源"：
- 枚举 ID，观察响应中是否有 uid/owner 字段不等于自己
- 枚举 ID，观察是否有数据返回（但无法确认属于谁）→ 标 pending
- 如果接口对不属于自己的 ID 返回空，说明有归属校验，IDOR 不成立

## 限购 / 库存

### 该测什么

1. **客户端限购参数**：user_limit_num、max_qty 等参数由客户端传入时，篡改是否生效？
2. **重复购买**：对限购商品重复下单，是否都能成功创建？
3. **库存绕过**：能否购买库存为 0 的商品？能否超库存购买？

### 什么不算漏洞

- 参数被接受但订单最终创建失败
- 参数被接受但订单被拦截在支付前

### 什么算漏洞

- 限购 1 件但实际成功创建了多笔有效订单
- 库存为 0 但订单创建成功

## 验证码 / OTP

### 该测什么

1. **暴力破解**：OTP 验证接口是否有频率限制？能否在有效期内遍历完验证码空间？
2. **绕过**：能否跳过验证步骤直接完成操作？
3. **重放**：使用过的验证码能否再次使用？

### 什么不算漏洞

- 发了 N 次错误请求没被限速 — 这是观察，不是漏洞
- 验证码错误返回的 message 不同（"不存在"vs"错误"）— 信息泄露极低

### 什么算漏洞

- 在 OTP 有效期内成功遍历出正确验证码，完成了账号绑定更换
- 不发送验证码直接调用验证接口返回成功
- 已使用的验证码再次调用返回成功

### 无法完成完整破解时

如果验证了"无频率限制"但无法在有效期内完成完整遍历（如 OTP 60 秒过期，6 位空间太大）：
- 上报 status: "pending"，severity: "high"
- 注明"已验证无速率限制，但未完成完整破解"
- 这算漏洞——无速率限制 + 可预测的 6 位空间 = 可行攻击，只是需要更高并发

## 竞态条件

### 该测什么

1. **重复创建**：并发创建同一资源（订单、领券、兑换）是否产生多个？
2. **余额竞态**：并发扣减积分/余额是否超额扣减？
3. **取消+操作**：取消操作和依赖操作并发是否导致状态不一致？

### 测试方法

用并发工具：
```bash
# 10 个并发请求
seq 1 10 | xargs -P 10 -I {} curl -s -X POST "..." -d "..."
```

### 什么不算漏洞

- 串行操作产生的正常行为（取消→重用是串行，不是竞态）
- 并发请求被服务端互斥锁拦截（这是正确的防护）

### 什么算漏洞

- 10 个并发领券请求，实际领到多张
- 并发创建订单，同一张券在多个订单中生效

## 加密

### 该测什么

1. **密钥恢复**：已知明文+密文对，能否恢复 AES 密钥？
2. **ECB 模式**：相同明文是否产生相同密文？能否通过块替换攻击修改明文？
3. **固定 IV**：CBC 模式下 IV 是否固定？能否做已知明文攻击？

### 什么不算漏洞

- 发现用了固定 IV / ECB 模式 — 这是观察
- 加密结果对同一明文有确定性 — 这是固定 IV 的特征，不是漏洞本身

### 什么算漏洞

- 用已知明文恢复了密钥，并成功解密了其他用户的密文
- 通过 ECB 块替换修改了加密数据（如把 user_id=123 改成 user_id=1）

## 文件上传

### 该测什么

1. **未授权上传**：是否需要认证？无 token 能否上传？
2. **类型绕过**：能否上传可执行文件（.php/.jsp/.svg）？
3. **路径穿越**：文件名能否包含 ../ 导致写到非预期位置？
4. **跨用户引用**：能否用别人的 file_id 作为自己的资源？

### 什么不算漏洞

- 需要有效 token 才能上传（无论 token 在 header 还是 body）— 有认证就不是未授权
- 只能上传图片类型 — 这是正确的限制

### 什么算漏洞

- 完全不需要任何认证即可上传文件
- 上传 .php 文件被服务端执行
- 用别人的 file_id 设为头像且确认文件属于其他用户
