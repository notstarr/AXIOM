# 渗透测试报告

**测试对象**：关务业务系统（cloud.longnows.cn 及其子系统：PubParam 公共参数、PMS 报关管理、CIQ 检疫、CMS、Entry 报关单、Common、customs-message）
**测试方式**：黑盒渗透测试（模拟外部攻击者，使用普通注册账号进行验证）
**测试日期**：2026-08（占位，请按实际填写）

---

## 一、结论摘要

本次测试共发现 **17 个安全问题：高危 8 个、中危 8 个、低危 1 个**。

核心结论一句话：**这套系统的"登录校验"和"权限校验"基本失效**。具体表现在三个方面：

1. **不用密码就能登录**：随便输一个密码，可以登录系统里的任意账号（高危 v004）；
2. **不用登录就能看数据**：公共参数接口完全开放，约 242 万条海关业务数据（含企业信用代码、行政处罚、两用物项管制清单等）任何人都能下载（高危 v001）；
3. **登录后可以操作任何人的数据**：查看、修改、删除、导出其他用户的数据均不需要任何额外权限，涉及检疫记录、报关单、下载任务、内部消息、账号密码等核心业务（v005、v007、v008、v014、v015 等）。

此外还发现 2 个 SQL 注入点（v002、v003），攻击者可以直接拖取整个数据库。

| 风险等级 | 数量 | 编号 |
|---|---|---|
| 🔴 高危 | 8 | v001、v002、v003、v004、v005、v006、v007、v008 |
| 🟠 中危 | 8 | v009、v010、v011、v012、v013、v014、v015、v016 |
| 🟡 低危 | 1 | v017 |

## 三、漏洞详情

### 🔴 v001 公共 API 大规模数据泄露（约 242 万条）

**是什么问题**：`/pubparam/api/v1/` 下的 86 个数据查询接口，全部**不需要登录、不需要任何凭证**，浏览器直接打开就能拿到全部数据。

**能造成什么危害**：
- 企业敏感信息：海关认证企业 8,091 条（企业名称 + 社会信用代码 + 海关编码）、海关行政处罚 55,750 条、海关失信企业 1,078 条、知识产权备案 132,842 条（含申请人姓名/企业名）
- 海关核心数据：FTA 国家税率 1,466,147 条、RCEP 税率 116,785 条、出口退税率 23,952 条、税则商品编码 12,079 条、法检目录 12,079 条
- 管制物项：危险化学品 3,116 条、易制毒化学品 64 条、出口管制清单 441 条、两用物项管制清单 173 条（含芥子气、沙林、VX 等化学武器前体及 CAS 号）
- 境外数据：泰国税则税率 304,360 条、统计代码 22,817 条
- 合计约 **2,423,659 条**记录，且接口 CORS 配置为 `Access-Control-Allow-Origin: *`（任意网站可跨域调用）

**复现方法**（无需任何账号）：

```bash
# 直接请求，无需登录，返回全部数据
curl "https://cloud.longnows.cn/pubparam/api/v1/enterpriseCredit/list?page=1&pageSize=10"
```

**证据**：累计验证 86 个端点均可未授权访问，累计记录数约 2,423,659 条；响应头实测 `Access-Control-Allow-Origin: *`。

**修复建议**：为该服务整体接入统一登录鉴权（网关层一次性解决）；企业信用代码、行政处罚、知识产权备案等涉及第三方主体信息的接口，按业务角色最小化开放；CORS 从 `*` 收紧为白名单域名。

### 🔴 v002 SQL 注入（complex/list 排序参数）

**是什么问题**：`/pubparam/api/v1/complex/list` 的 `sort`（排序）参数会直接拼进数据库语句。攻击者在排序字段里夹带数据库命令，就能让数据库"回答"任意问题——比如"数据库名字的第一个字母是不是 p？"——对就报错、错就正常，逐个字母把整个数据库内容问出来。这个接口同样**不需要登录**。

**能造成什么危害**：数据库中所有数据（包括上表全部内容）可被完整拖库；已实测确认可读取数据库名（`pubparam`）、版本等。

**复现方法**：

```bash
# 条件为真时返回 500（数据库报错），为假时返回 200（正常列表）
# 示例：判断当前数据库名长度
curl "https://cloud.longnows.cn/pubparam/api/v1/complex/list?sort=(SELECT ... 条件 ...)"
```

**证据**：
- 已成功提取：数据库名 `pubparam`；数据库版本首字符 `8`、长度 6；当前库首表名首字符 `b`、长度 8
- 使用 `sys.sys_config` 错误型布尔盲注，稳定绕过 WAF 对 `IF / CASE WHEN / mid / left / substr / ifnull / nullif / like / concat` 等关键字的拦截

**修复建议**：排序字段改为白名单——只允许前端传预定义的列名（如 `sort=taxCode`），其余一律拒绝；同时给数据库账号降权。

---

### 🔴 v003 SQL 注入（banList/list，HTTP/2 可绕过 WAF）

**是什么问题**：与 v002 同类的注入点，位于 `/pubparam/api/v1/banList/list`（禁止进出口商品目录，512 条，含虎骨、犀牛角等濒危物种数据）。更严重的是：**把请求从 HTTP/1.1 换成 HTTP/2 发送，WAF 防火墙就完全检测不到**。

**能造成什么危害**：攻击者可绕过现有防护，把整个数据库内容逐条提取出来。

**复现方法**：

```bash
# 使用 HTTP/2（curl 的 --http2）发送同样payload，WAF 无任何拦截
curl --http2 "https://cloud.longnows.cn/pubparam/api/v1/banList/list?sort=<注入语句>"
```

**证据**：
- 条件为真时稳定返回 500（数据库错误），为假时稳定返回 200（正常数据），可逐字符提取
- 确认数据库为 MySQL 8.0.28，数据库名 `pub_param`

**修复建议**：同 v002（排序白名单）；另外检查 WAF 的 HTTP/2 检测配置，确保 HTTP/2 流量同样过检。

### 🔴 v004 任意密码可登录所有 PMS 账号（认证绕过）

**是什么问题**：登录接口不校验密码。我们用**完全随机的乱码密码**（如 `e396f0d65d08`）去登录，居然全部成功。从用户列表接口拿到的 10 个真实手机号逐一验证，全部能登录。

**能造成什么危害**：任何人只要知道（或枚举到）手机号，就能登录系统内全部 22 个 PMS 账号——包括企业账号、运维账号、系统账号。结合其他越权漏洞，等于拿到了整个系统的控制权。

**复现方法**：

```bash
POST /pms/api/v1/pmsUser/login
{"account": "13547934520", "password": "<任意随机字符串的MD5>"}

# 响应：code:0，返回有效 accessToken
```

**证据**：以下账号均用随机密码登录成功：13547934520（黄佳威）、18676931500（陈世欣）、13790162768（张镇海）、13432843703（杨仕馀）、18310442150（刘洋）、13488940280（汪强）、13968850000（苏州金一）、11111111111（下载专用）、12345678922（运维人员）、99999999999（系统）。影响范围为全部 22 个 PMS 用户。

**修复建议**：立即排查登录逻辑（大概率存在"密码校验结果未生效/被跳过"的代码分支），修复后强制全部用户改密，并增加登录失败锁定与登录告警。

### 🔴 v005 任意重置他人密码（账号接管）

**是什么问题**：重置密码接口 `/pms/api/v1/pmsUser/resetPwd` 不校验"你是谁"——任何登录用户，只要在请求里填上**别人的用户 ID** 和新密码，就能把别人的密码改掉。

**能造成什么危害**：接管任意账号。配合 v004（不用密码就能登录），攻击者可以接管系统内全部账号。

**复现方法**：

```bash
POST /pms/api/v1/pmsUser/resetPwd
{"userId": "01M10NHX1TR4T65GXDPFA7HZ8C", "newPwd": "<新密码MD5>"}

# 响应：{"code":0, "data":true} —— 密码已被修改
# 随后用新密码登录目标账号（黄佳威/13547934520），成功获得有效 accessToken
```

**证据**：使用运维账号（19129430218）的 Token 成功重置黄佳威账号密码并用新密码登录成功。**测试完成后已用 system 账号将密码恢复原状**。

**修复建议**：重置密码仅允许"本人（验证旧密码）"或"管理员在管理后台操作"；服务端校验"当前登录用户只能改自己的密码"。

### 🔴 v006 普通账号可领取"跨系统万能通行证"

**是什么问题**：`POST /pms/api/v1/pmsWormHole/` 端点会给任意登录用户发一个"wormhole 通用 Token"。拿着这个 Token，可以访问 PMS / CMS / CIQ / Basic / Entry / Common **全部子系统**，包括普通 Token 本来无权访问的审批（approve）、提交（submit）、保存（save）等管理操作。

**能造成什么危害**：普通低权限用户一键提权为"全系统访问"。叠加 v004（任意密码登录），攻击者**零门槛**获得全微服务权限。

**复现方法**：

```bash
POST /pms/api/v1/pmsWormHole/
Authorization: Bearer <任意有效PMS Token>

# 响应：返回 wormhole Token，可访问 CIQ/CMS/Basic/Entry/Common 全部微服务
```

**证据**：使用普通运维账号 Token 成功获取 wormhole Token，并用其访问了普通 Token 无法访问的管理端点。

**修复建议**：此类跨服务凭证不应发放给终端用户；如业务必需，改为服务端间点对点调用并绑定具体权限清单，禁止"一票通行"。

---

### 🔴 v007 检疫记录可越权查看/删除

**是什么问题**：CIQ 检疫模块的记录接口不区分"这条数据是谁创建的"。A 用户能看到 B 用户创建的全部检疫记录，还能把 B 的记录删掉。

**能造成什么危害**：检疫申报属于敏感业务数据，跨企业可见可删，既泄露业务机密，也可能破坏他人在途申报。

**复现方法**：

```bash
# 1) 列表接口返回了其他用户（19129430218）创建的全部记录
GET /ciq/api/v1/inspectionQuarantineHead/list

# 2) 删除其他用户的记录（uid 支持数组，批量删）
POST /ciq/api/v1/inspectionQuarantineHead/remove
["<其他用户记录的uid>"]
# 响应："删除成功"
```

**证据**：账号 13547934520（黄佳威）成功查看并删除了账号 19129430218（运维）创建的检疫记录。

**修复建议**：列表查询强制按"创建人/所属企业"过滤；删除、修改前校验记录归属，非本人数据返回 403。

---

### 🔴 v008 下载任务可越权删除

**是什么问题**：`POST /customs-message/api/v1/entryDownloadTask/remove/{id}` 不校验任务归属。任何登录用户填上别人的任务 ID，就能把别人的报关单下载任务删掉。

**能造成什么危害**：可恶意删除其他企业的在途下载任务，影响正常报关作业。

**复现方法**：

```bash
POST /customs-message/api/v1/entryDownloadTask/remove/01M11VYM9ARM39Q2CEMNF38XVR
Authorization: Bearer <黄佳威账号Token>   # 任务实际由运维账号创建

# 响应：{"code":0, "message":"删除成功", "data":1}
```

**证据**：连续删除两个由运维账号创建的任务均返回"删除成功"；无 Token 访问返回 401（说明接口有登录校验、缺的是归属校验）。

**修复建议**：同 v007——删除前校验任务归属；同类的 `entryDownloadHead/remove` 存在相同问题，需一并修复。

### 🟠 v009 公共 API 未授权访问（首批确认）

**是什么问题**：v001 的初步版本。首批确认 6 类数据无需登录即可访问：商品编码 12,079 条、两用物项 1,796 条（含 CAS 号）、国家协定代码 121 条、CCPIT 优惠类型 78 条、224 个参数类型元数据；另确认 `classification/conversations/messages/save` 写接口同样无需认证。

**证据**：以上端点均无 Token/Cookie 直接返回数据。

**修复建议**：同 v001，网关层统一加鉴权。

### 🟠 v010 试用申请可未授权批量创建

**是什么问题**：`/idp/PlatformCenter/SysFreeTrial/Create` 不需要登录就能创建试用申请，申请人姓名、手机号、公司名全由请求方随便填，无任何限制。

**能造成什么危害**：可无限量刷试用申请（返回的自增 ID 01539→01542→01545 可枚举总量），污染销售线索、批量注册垃圾试用。

**证据**：不带任何 Token 调用返回 `Success:true` 与自增 ID；无速率限制。

**修复建议**：加登录/验证码 + 频率限制；后端校验会话信息而非信任请求体。

### 🟠 v011 任意用户可创建新系统账号

**是什么问题**：`pmsUser/create` 不做角色校验，任何登录用户都能创建新系统用户，且新用户还能继续再创建更多用户（无限裂变）。

**证据**：用运维账号创建新用户成功（uid=01M117X2ZSQECH7RHBGWAJV3BZ），新用户可登录并查看全量用户列表。

**修复建议**：用户管理接口仅限管理员角色调用（服务端 RBAC 校验）。

---

### 🟠 v012 越权创建企业信息

**是什么问题**：`pmsOrganCorp/create` 未校验角色。运维角色（业务上不应管企业档案）成功创建了企业信息并出现在企业列表中；无 Token 时返回 401，说明缺的是"角色权限"而非"登录校验"。

**修复建议**：企业管理接口限定企业管理员/特定角色。

---

### 🟠 v013 子系统后端权限校验缺失（前端拦、后端不拦）

**是什么问题**：前端页面对无权限用户显示"您未开通业务权限"，但这只是前端拦截——后端 API 照单全收。实测 6 个写操作端点无一返回 401/403：

| 端点 | 实际响应 |
|---|---|
| POST /ciq/api/v1/inspectionQuarantineCertificate/create | ✅ 创建成功（返回新 UID） |
| POST /entry/api/v1/entryHead/create | ✅ 创建成功（返回新 UID） |
| POST /ciq/api/v1/inspectionQuarantineHead/create | 业务校验错误（"输往国家必填"） |
| POST /ciq/api/v1/export | 业务校验错误（"导出表头不能为空"） |
| POST /ciq/api/v1/import | 500 请求格式错误（已穿透认证层） |
| POST /cms/api/v1/enterpriseGoods/create | 业务校验错误（"商品料号必填"） |

**修复建议**：把前端"业务权限开通"的判断在**后端**（网关或服务层）实现一遍，未开通业务的请求直接 403。

---

### 🟠 v014 报关单可越权批量导出

**是什么问题**：`POST /entry/api/v1/export` 不按用户过滤数据。用一个从未创建过报关单的账号、空搜索条件调用，就把系统里**其他用户创建的全部报关单**（33 条，createUserId=运维）导出来了。

**证据**：双账号交叉验证——账号 13547934520 导出的数据与运维账号的数据完全一致，包含他人创建的记录。

**修复建议**：导出接口强制附加"当前用户/所属企业"过滤条件。

---

### 🟠 v015 内部消息可越权读/改/删/伪造

**是什么问题**：站内消息的列表接口过滤是好的，但**单条操作接口全都不校验归属**：读详情（getDetail）、标记已读（readOne）、改标签（tag）、删除（remove）、甚至**创建（create 可任意指定收件人 userId）**。

**证据**：双账号验证——用户 A（13800138990）创建消息后，用户 B（13800138991）成功读取详情、标记已读、改标签、删除，并向 A 的收件箱注入伪造消息。

**修复建议**：所有按消息 ID 操作的接口校验"该消息属于当前登录用户"；create 端点的收件人由服务端指定，不信任请求参数。
