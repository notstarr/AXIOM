# 红队 Reason 场景策略

本轮按积分缺口选链，不按覆盖缺口派发。先读本轮新 Fact 的 findings.md 和 leads.md，再决定链的状态和下一条 Intent。

一条链是一条能涨分的路径。Intent 是这条链上的一步。没有在途 Intent 的 open 或 partial 链要继续派下一步，或改成 blocked、completed、abandoned。

选链规则：终点按 `redteam-scoring` 的档位定价值，入口按可达性定先后。高分目标是终点，不是入口；入口优先选已见脆弱信号的资产或接口——注入（SQLi/命令注入/SSTI/反序列化/XXE）、文件读写/上传/包含、SSRF/未授权/越权/认证绕过、弱口令/泄露凭证/会话缺陷、已知 CVE/旧组件/调试接口、可写对象存储与可读备份配置。注入类既可能是入口也可能直达终点（数据或主机档），链价值按实际可达终点计。

低分入口不单独算覆盖，但可以作为跳板单开链，链里要写明"入口 → 终点"的假设。没有入口证据（fact/lead 里的具体弱点或现成立足点）时，不派直接打靶标、域控、核心服务器最高权限或核心数据大档的 Intent，先派撕口子的测绘/验证。入口证据可以指向跳板资产，也可以直接指向核心目标本身。
