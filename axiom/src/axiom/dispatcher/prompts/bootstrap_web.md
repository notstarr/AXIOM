# Bootstrap 子提示词：Web／API

本文件只补充 Web 与 API 目标的引导工作流。阶段边界、Scope、技能、三个产物和 `FINISH` 协议仍以主 `bootstrap.md` 为准。

## 目标身份

先锁定一个明确的网站、域名、URL 或 API 入口，并记录身份依据。只有满足以下任一关系的资产才属于当前目标：

- 由测试入口直接访问、跳转或返回；
- 被当前页面、JS、Source Map、OpenAPI、响应头、证书或已确认接口直接引用；
- 被任务 Hint、项目知识或显式网络 Scope 明确列出。

相似域名、搜索结果、历史流量中的其它 Host 和本机已有项目不得因为名称接近而并入当前目标。没有显式 Scope 时也不能把 Origin 当成自动网络授权；实际访问仍遵循任务边界和工具 Guard。

## 首轮发现顺序

1. 验证入口的协议、状态、标题、跳转链、证书和基础技术栈，记录每项证据来源。
2. 检查入口可见页面、`robots.txt`、`sitemap.xml`、显式 JS、Source Map、公开文档、OpenAPI/Swagger、GraphQL 和错误响应中暴露的路径。
3. 从真实页面和脚本提取 API Host、路径、HTTP 方法、参数、对象标识、认证入口和角色入口；区分页面路由、静态资源和后端接口。
4. 仅在有证据时扩展到关联子域名、端口和服务；不要用大字典或无依据路径猜测代替入口驱动的发现。
5. 对登录、注册、找回、邀请、上传、搜索、订单、申诉、投诉、审批等已出现的业务入口，只整理身份、对象和后续验证线索，不在 Bootstrap 深挖完整攻击链。

## 三个产物的 Web 细节

- `asset_inventory.md`：记录当前域名/入口、跳转、关联 Host、端口、服务、页面、JS、接口、方法、参数、认证方式和证据位置。
- `initial_leads.md`：记录尚待 Explore 验证的接口、权限边界、对象引用、业务流程和客户端暴露线索，并说明证据与缺失条件。
- `findings.md`：只记录已通过真实请求或等价证据确认的漏洞。普通 `200`、版本号、公开路径、缺少安全头、理论 CORS/鉴权风险和只存在于 JS 的字符串不得写成漏洞。

三个文件必须使用主提示词规定的“目标类型／当前目标身份／身份判断依据”头部，其中目标类型填写 `Web`。
