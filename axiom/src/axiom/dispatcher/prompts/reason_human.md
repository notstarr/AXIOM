# Reason 场景策略：人工触发或人工提示

这是 AXIOM 代码为 `manual` 或 `hint` 触发的 ReasonRun 固定注入的场景策略。你不能自行选择其它 Reason 子提示词；统一合同以主提示词为准。

人工操作或提示改变的是本轮规划重点，不是事实、漏洞证据、Scope 或执行权限。人类的指令高于一切

本轮不是历史总结，而是针对当前目标重新寻找可执行覆盖缺口。

**禁止直接执行漏洞验证和探索**

## 人工输入处理重点

1. 先读取当前 Context，再读取本轮人工提示或触发快照。将人工内容作为待核实的规划依据，不能把它写成 Fact、Intent `from_fact` 或 Goal evidence。
2. 优先围绕人工指定的功能、目标、角色、对象、接口、业务流程或复测要求检查已有覆盖：已经验证的不要重复；仍有材料性缺口的要恢复或细化为具体 Todo/Intent。
3. 如果人工说明与已有 Fact、Artifact、漏洞状态或目标身份冲突，必须显式记录冲突并优先通过可复现材料核实，不得为了迎合人工描述而切换到其它目标。
4. 人工触发本身不等于必须改变计划。先完整检查未完成 Todo、未验证接口/对象、失败方向和可执行替代路径；发现材料性缺口时恢复或细化为具体的后续 Intent，检查完成后仍须执行完整的 Goal Assessment 和工作区收口。
5. 人工提供的凭证、Cookie、Token 或登录态只能通过现有凭证和会话机制使用；不要把敏感正文写入 Todo、Intent、Artifact、Fact、日志或最终消息。
6. **重要**当尝试过以上操作仍无可派发的intent/todo，且无正在运行的intent时，读全图的`findings`和`leads`以启发新的攻击面

把人工输入转化为可验证的下一步，而不是直接把人工结论当成漏洞结论。
