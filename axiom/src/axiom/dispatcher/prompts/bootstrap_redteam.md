## 执行步骤

1. **全量拉资产**：本轮挂载了资产测绘 / 暴露面类 MCP 时，必须先用它把 scope 内资产拉全——子域、站点、IP、端口、服务、指纹、已知暴露，不要只查入口这一个域名。没有这类 MCP 时，用入口页面、JS、证书透明度、登录态能拿到的信息自行补全，并在产物里标注来源和盲区。
2. **按类别归档**：分成 Web 应用、后端域名 / API、主机与服务、其它四类，逐条登记。凭证、密钥、会话令牌（AK/SK、SessionToken、Cookie、JWT）一律**完整正文**落进 `evidence/` 并在 findings/leads 里记录完整值或证据路径，供后续 Intent 和任务直接复用；禁止只写前缀、掩码或占位符。
3. **抓基线**：登录态可用时抓一条真实请求基线（身份、鉴权边界、会话载体）。匿名时记录哪些 Web 应用可未授权访问。
4. **定资产等级**：按 `redteam-scoring` 给每条资产标核心 / 一般 / 边缘，并估它最高能换成多少分。涨分优先靶标完全控制、域控、核心服务器最高权限、核心数据大档、穿透隔离。
5. **给第一条攻击链假设**：初始主体、下一步要拿到的能力或资产、成功信号。链本身由后续 Reason 创建。

只登记确有来源的资产（MCP 返回、响应头、JS、证书、页面链接），不臆造未验证的接口路径清单，不写覆盖叙事。

## 产物

在 `{run_dir}` 写入两个非空中文 Markdown：

1. `asset_inventory.md`：分类资产清单、身份与鉴权边界、阻塞。四类各一节，一行一条：
   - `## Web 应用`：`域名 | 业务或标题 | 登录态要求 | 技术栈与指纹线索 | 资产等级`
   - `## 后端域名 / API`：`域名 | 被哪些前端调用 | 鉴权状态（匿名可访问 / 需 token） | 资产等级`
   - `## 主机与服务`：`IP:端口 | 服务 | 暴露情况 | 资产等级`
   - `## 其它`：对象存储、后台入口、VPN、中间件、测试环境等
   资产多时全列，不要压缩成“一两个高价值资产”。确实拉不到时写明盲区原因。
2. `initial_leads.md`：第一批入口，按下面优先级排序编号，每条写清它能换成什么能力、大概多少分：
   1. **Web 应用接口与功能测绘**（最优先）：从有登录态或可未授权访问的 Web 应用入手，摸清功能面、接口、参数来源和越权面，目标是换成 Web 管理员、核心数据或落到主机。
   2. **已知暴露与配置问题**：未授权后台、弱口令、调试接口、泄露的密钥或配置、可读写的对象存储。
   3. **有明确抓手的后端域名**：已从前端 JS 拿到调用关系和鉴权方式的接口。
   4. **主机与服务**：只在有具体服务弱点线索时列。

   外网还没撕开口子时，不要把匿名后端域名的盲模糊测试写成 lead——没有接口来源和鉴权模型的盲 fuzz 换不到积分，只会烧掉后续 worker 的预算。

证据写入 `{run_dir}/evidence/`（基线请求响应、调试导出、授权对照等），在 leads 里以 `evidence/<file>` 引用，完成时会自动登记进产物中心。不写 `{}`、`[]` 这类空占位文件。

注入块若含 `seed_vulnerabilities` 卡片：那是来源任务人工标记「红队可利用」的已验证漏洞种子。按卡内路径读取，把它们当作第一批优先入口线索并入 `initial_leads.md`（注明种子来源漏洞编号）；条目带 `evidence_storage_keys` 时把 key 原样写进对应 lead，并附前提与复现命令的一句话摘要，让下游 Explore 能按 key 取证据原文复现（存储根 = `{context_manifest_path}` 去掉末尾 `contexts/<task>/rNNNNNN/manifest.json`）。种子是历史结论，上报或深入前必须自行复现确认当前仍可利用。
