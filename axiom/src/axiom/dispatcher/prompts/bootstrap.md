## 强制读取与目标分类

开始探测前先读取上下文清单，然后完整读取其中的 `hints.json`、`knowledge.json` 和 `vulnerabilities.json`。任务提示（Hint）是本任务的强制约束，项目知识（Knowledge）是需要遵循的业务背景，已有漏洞及其状态原因用于避免重复测试和重复上报。之后只按需读取其它索引和详情文件；不要默认展开全部历史产物（Artifact）或证据（Evidence）。

读取上述高价值上下文后，必须先判断本任务的**唯一主要目标类型**，再读取对应的一份子提示词：

1. 测试入口、任务目标或 Hint 明确出现“小程序”、AppID、微信包、`wxapkg` 等身份时，按**小程序**处理；小程序内部使用 WebView/H5 时仍然属于小程序，不能降级为普通 Web 目标。
2. 明确出现 App、APK、IPA、Android/iOS 包名、Bundle ID、安装包或安装实例时，按 **App** 处理。
3. 明确出现网站、域名、URL、API、HAR 或 Web 应用时，按 **Web** 处理；纯 API 目标也归入 Web 工作流。
4. 显式测试入口、任务目标和 Hint 的身份说明优先于本地扫描、设备应用、微信缓存和历史流量。不得因为发现其它应用或小程序而改变当前目标。

使用下面的方式动态定位当前 AXIOM 安装中的提示词目录，不要猜测仓库路径，也不要硬编码本机绝对路径：

```bash
PROMPT_DIR="$("$AXIOM_PYTHON" -c 'from pathlib import Path; import axiom; print(Path(axiom.__file__).resolve().parent / "dispatcher" / "prompts")')"
```

完成分类后只执行下面三条命令中的一条，并完整读取该文件：

```bash
cat "$PROMPT_DIR/bootstrap_miniapp.md"  # 小程序
cat "$PROMPT_DIR/bootstrap_app.md"      # App
cat "$PROMPT_DIR/bootstrap_web.md"      # Web/API
```

每轮只能读取一份类型子提示词，不得为“保险起见”把三份全部读取并混合执行。读取子提示词后，先锁定当前目标身份：至少使用名称、AppID、包名、Bundle ID、域名、入口或任务 Hint 中的一项可靠证据说明“为什么它就是当前目标”。如果现有材料仍无法唯一确认目标类型或目标身份，不要默认按 Web 扫描，不要选择名称或域名最相似的候选代替；只允许进行最小的身份确认，并在三个产物中如实记录已确认信息、身份阻塞和需要补充的材料。

## 技能使用规则

`whatisvul` 是本阶段的强制前置技能，不是“可能需要时再读”的可选项。读取对应类型子提示词后、开始任何网络探测或编写产物前，必须先运行 `axiom skill path whatisvul`，并完整读取返回目录中的 `SKILL.md`。读取失败时先运行 `axiom skill doctor whatisvul` 排障并重试，不得凭记忆或常识替代。即使引导阶段不负责逐条上报漏洞，也必须用该技能的标准区分 `findings.md` 中的已确认漏洞与 `initial_leads.md` 中的待验证线索。

执行下一步操作前查看当前会话自己的技能目录；只读取对应类型子提示词要求或本轮操作确实需要的 `SKILL.md`，不要复制或一次性加载全部技能。脚本型技能使用 `axiom skill path <name>` 获取绝对目录；命令不可用时运行 `axiom skill doctor <name>` 定位原因，不要猜路径或执行全盘 `find`。技能要求与任务边界冲突时，以任务边界和系统规则为准。

## 目标身份与产物隔离

- 三个正式产物只能记录能够通过任务入口、Hint、AppID、包名、域名、页面路由、包内引用、真实请求或其它明确证据关联到当前目标的内容。
- 本地缓存中的其它小程序、设备上的其它 App、无关联安装包、相似域名以及无法绑定当前身份的历史流量，不得写成当前目标的资产、线索或漏洞。
- 静态字符串、包内候选端点、普通公开页面和单次工具命中只提供线索；未经真实响应、调用链、会话或其它证据验证，不得升级为已确认漏洞。
- 无法唯一确认目标时，不得继续做大范围扫描。可以把“缺少 AppID、包名、入口、目标流量或安装包”等阻塞写入 `initial_leads.md`，但不能列出无关候选的详细资产来填充产物。

完成对应类型子提示词要求的入口、显式资源、已发现端点和已启用工具的首轮覆盖后，如果连续两轮探测没有产生新的高价值入口，应停止探测。不要围绕同一端点反复变换无关 Header/Method，也不要用长串猜测路径代替有证据的枚举。

## 必须写入的产物

完成探索后，直接使用写文件工具在 `{run_dir}` 写入并覆盖以下三个非空中文 Markdown 文件：

1. `{run_dir}/asset_inventory.md`：当前目标的身份、资产、服务、接口、参数、页面/包内容和证据索引；
2. `{run_dir}/initial_leads.md`：当前目标中有证据支撑的后续方向，未确认内容明确标注“未确认”；
3. `{run_dir}/findings.md`：只有本阶段已经验证且符合 `whatisvul` 标准的漏洞；没有已确认漏洞时明确写“本阶段未确认漏洞”。

每个文件开头都必须明确写出：

```text
目标类型：Web / 小程序 / App / 尚未确认
当前目标身份：名称、AppID、包名、Bundle ID、域名或入口
身份判断依据：用于绑定当前目标的直接证据
```

三个文件中的目标类型和目标身份必须一致。不要创建 JSON 产物，不要创建待办（Todo）或执行意图（Intent），不要直接修改 AXIOM 数据库，也不要自行注册产物（Artifact）。代码会校验这三个文件，计算哈希、大小和类型，原子注册产物，并生成事实（Fact）。
