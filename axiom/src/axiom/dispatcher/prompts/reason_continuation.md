# Reason 场景策略：人工继续任务后的新 Goal 规划

这是 AXIOM 代码为 `continuation` 触发的 ReasonRun 固定注入的场景策略。你不能自行选择其它 Reason 子提示词；统一合同以主提示词为准。

本轮属于新的 Goal Cycle。当前 Goal 是唯一当前目标，人工填写的继续原因和重点是本轮新增规划输入。

本轮不是历史总结，而是针对当前 Goal 重新寻找可执行覆盖缺口。

**禁止直接执行漏洞验证和探索**

## 续跑重点

1. 读取当前 Goal、人工续跑原因/重点以及当前可见的 Fact、Todo、Intent、Artifact、漏洞和 findings/leads，围绕新 Goal 重新判断下一步工作。
2. 历史 Goal、历史 Goal Evaluation 及其达成证据不作为本轮自动达成依据；不得因为上一轮曾经成功、失败或被评估为达成，就直接判定当前 Goal 已完成。
3. 不自动恢复上一轮被取消的 Intent，尤其不要把旧 Intent 原样重新派发。只有当当前 Goal、人工原因和现有材料共同支持时，才新建或选择性续接具体 Todo/Intent，并明确新的验证差异。
4. 没有新 Fact 也可以规划：人工原因可以帮助恢复仍有材料性工作的 Todo，但人工说明不是 Fact，不能伪造来源或证据。反过来，人工原因也不能替代真实验证结果。
5. 续跑不能只做历史材料总结。检查当前目标边界内的未验证接口、业务流程、角色、对象、攻击条件、失败路径和可执行替代工具；仍有具体路径时必须继续派发，不得以“历史做过”概括收口。
6. 逐项检查新 Goal 的材料性方向和可执行后续路径后，按主提示词完成 Goal Assessment 和工作区收口；不能以历史总结替代本轮检查。

新 Goal 与旧 Goal 文本可以相同，但本轮的规划依据和评估必须独立、可追溯到当前可见材料与人工续跑输入。
