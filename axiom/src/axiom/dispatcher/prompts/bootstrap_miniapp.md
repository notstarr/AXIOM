# Bootstrap 子提示词：小程序

本文件只补充小程序目标的引导工作流。阶段边界、Scope、技能、三个产物和 `FINISH` 协议仍以主 `bootstrap.md` 为准。小程序使用 WebView/H5 只是其实现方式，目标类型仍填写“小程序”。

## 唯一目标绑定

必须先用任务入口、Hint、名称、AppID、页面标题、业务 Host、二维码或人工提供材料锁定当前小程序。名称相似不是充分证据；只有微信缓存中存在某个包也不是充分证据。未能唯一匹配时停止包分析和大范围流量归类，不得选择“最可能”的其它小程序代替。

微信缓存中的其它小程序，包括混元、CodeBuddy 或任何与任务身份不一致的包、页面、域名和接口，都不得进入当前任务的三个正式产物。

## Miniapp Skill 固定工作流

如果当前 Lease 披露了 `miniapp` Skill，完整读取其 `SKILL.md`，并严格执行：

```text
status → 必要时 probe → 选择唯一 target_id → prepare
```

- `status`：优先检查是否已有与当前名称、AppID、页面或业务 Host 一致的可复用结果。
- `probe`：只有没有可用结果时才探测未解包包组；探测结果只是候选清单，不等于当前目标。
- 选择 `target_id`：必须写明它与当前任务身份匹配的直接证据；不能只凭最近修改时间、排序位置或相似名称选择。
- `prepare`：每轮只准备已确认的一个目标；不要批量分析其它缓存包来填充攻击面。
- 若没有匹配目标、Skill 未启用或脚本不可用，如实记录阻塞和所需材料，不要猜路径、全盘搜索或换测其它小程序。

## 静态包与 Reqable 流量

1. 从已确认目标的 `manifest.json`、`summary.md`、`traffic_workflow.md`、主包/分包、页面路由和配置中提取 AppID、页面、WebView、Host、API、参数和业务 code。
2. 静态字符串、正则命中和包内 API 候选只能写为“未确认线索”，不能证明接口真实存在、当前仍部署或存在漏洞。
3. 如果当前阶段启用了 Reqable MCP，优先读取真实历史或实时流量，确认请求 Host、路径、方法、身份、对象 ID、参数和响应；不得把无 AppID、页面、会话或业务链关联的历史流量归入当前目标。
4. WebView/H5 地址只有能通过 AppID、页面路由、包内调用、跳转链或真实会话绑定当前小程序时，才能写入资产。不能因为它是 Web URL 就脱离小程序身份扩展到其它站点。
5. Bootstrap 只整理登录态、用户身份、对象、页面和业务流程入口；复杂权限、业务逻辑和漏洞利用交给后续 Explore。

## 三个产物的小程序细节

- `asset_inventory.md`：记录名称、AppID、版本/目标 ID、主包/分包、页面路由、WebView、关联 Host/API、Reqable 请求证据和文件索引。
- `initial_leads.md`：记录静态候选端点、待恢复流量、登录后接口、身份/对象/角色边界和业务流程方向，并明确哪些仅来自静态包。
- `findings.md`：只记录已经通过真实请求、包内确定调用链或其它充分证据确认的漏洞；敏感字符串、候选接口和其它缓存小程序的发现不得写入。

三个文件必须使用主提示词规定的“目标类型／当前目标身份／身份判断依据”头部，其中目标类型填写 `小程序`。
