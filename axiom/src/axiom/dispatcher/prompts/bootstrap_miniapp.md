# Bootstrap 子提示词：小程序

本文件只补充小程序工作流，所有通用边界、技能、产物与完成合同以主 `bootstrap.md` 为准。小程序中的 WebView/H5 仍按小程序处理。

## 唯一目标绑定

目标类型填写 `小程序`。必须用名称、AppID、页面标题、页面路由、业务 Host、任务材料或当前会话证明目标身份；微信缓存中名称相似的其它小程序不得代替当前目标。

开始静态或流量分析前，完整读取 `miniapp` Skill，并严格执行：

```text
status → 必要时 probe → 选择唯一 target_id → prepare
```

选择结果必须与当前名称或 AppID 一致；没有匹配项、存在多个无法区分的候选或 `prepare` 失败时停止扩展，只记录身份阻塞。不得选择混元、CodeBuddy 或其它缓存目标来填充结果。

## 小程序工作流

1. 从已确认 target_id 的主包、分包、插件、配置和 Source Map 收集 JS，沿页面表、分包声明、`require`、动态加载、组件引用和 WebView 入口递归补全。
2. 从 JS 提取页面路由、组件、API Host/路径、方法、参数、对象 ID、登录态、角色判断、业务动作、状态值、上传下载、WebSocket 和云函数调用，区分业务代码、平台框架与第三方 SDK。
3. 存在登录后页面或人工凭证时，安全恢复当前 AppID 的会话，访问对应路由并补充登录后 JS、分包、接口配置和动态资源；不得用其它微信会话或缓存小程序代替。
4. 当前阶段具备 Reqable/MCP 能力时，优先用与当前 AppID、页面路由、页面操作或会话绑定的历史/实时流量确认静态候选；同一 Server 的无关流量不得纳入。
5. WebView/H5 只有能追溯到当前 AppID、页面路由、JS 调用或真实会话时才能并入业务链。
6. JS-first 后再补充权限、隐私声明、组件、云环境和其它小程序资产；静态敏感字符串或端点不能单独成为已确认问题。

## 产物补充字段

- 资产清单补充名称、AppID、target_id、包来源、主包/分包/插件、页面与组件、WebView、关联 Host、真实流量和登录前后覆盖。
- 初始线索补充静态候选接口、页面权限、对象/角色边界、业务状态、流量恢复和所需验证条件。
- 已确认问题必须绑定当前 AppID，并由真实请求、运行时行为、完整调用链或等价证据支撑。
