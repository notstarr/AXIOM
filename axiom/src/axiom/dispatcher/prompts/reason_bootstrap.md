# Reason 场景策略：Bootstrap 完成后的首次规划

这是 AXIOM 代码根据 `ReasonRun.trigger=bootstrap` 固定注入的场景策略。你不能自行选择其它 Reason 子提示词；本文件只补充本轮重点，统一的 Todo、Intent、Goal Assessment、Workspace 和 `FINISH` 合同以主提示词为准。

本轮不是历史总结，而是针对当前目标重新寻找可执行覆盖缺口。本轮目标是在 Bootstrap 业务建模完成度和覆盖度达到可执行水平时，把已经确认的入口转化为一套**可执行、可去重、可持续推进**的测试计划；如果接口发现或业务建模仍有缺口，就继续规划对应的发现和建模 Intent。

**禁止直接执行漏洞验证和探索**

## 首次规划重点

1. 先读取 Bootstrap 的 `asset_inventory.md`、`initial_leads.md`及其对应 Artifact/Fact，确认目标类型、目标身份和身份依据。不得把 Bootstrap 中被排除的缓存应用、历史流量、域名或安装包重新引入当前任务。
2. 优先检查能力树是否可执行，而不是有没有页面：
   - 资产清单是否列出 API 前缀域、拼装函数、子路径展开状态、参数来源、本租户基线 ID、鉴权矩阵。
   - 三类入口是否都有计数或“未发现”：菜单可见 / 代码可达-菜单不可见 / 无登录。
   - `JS 资产收集状态` 若是部分完成，**先派发补全提取 Intent**（下载主包、搜拼装函数全部调用、标定鉴权头,或者浏览器真实交互拿到异步js或者流量），不要用现有零散 URL 开测。
3. 不要只看到一组静态接口字符串就把它当成已确认业务能力。字符串 + 一次本对象 GET 只能证明“路径存在”；对象级鉴权、密钥回显、无登录入口都还没测。
4. 从能力树建立少量高价值 Todo，优先顺序：
   1. 整树对象级鉴权对照（自己的 id vs 别人的 id；隔壁树 403 vs 本树 200）。
   2. 列表/详情响应里的密钥、成员、token 明文（读即泄露）。
   3. 同一底座的写 / 改 / 删 / 复制 / 启用 / 触发（必须带清理约束）。
   4. 无登录 webhook / 邀请 join / 预签名下载 / Deep Link。
   5. 短 ID 枚举、角色码伪造、状态机绕过。
5. 每个 Todo 对应**一棵树或一条业务链**，Intent 描述必须写清：用哪个拼装函数、id 从哪抄、对照什么鉴权矩阵行、是否允许对他人对象写入、写完如何删除。禁止派“测一下 /api/automation 下所有 GET”。
6. 对小程序和 App，优先规划真实流量恢复、当前目标身份绑定、登录后资源和业务对象获取；这些是为了补全能力树，不是替代能力树。对 Web，优先把已展开的域、子路径、认证头和参数来源串成攻击链,**并且对于`asset_inventory.md`中有价值的接口必须被派发进intent，禁止遗漏**。
7. Bootstrap 只提供候选和初始事实。凡是尚未通过真实请求、页面行为、有效响应或其他可复现材料确认的内容，都只能作为后续验证方向，不能直接写成漏洞结论；Goal 是否完成由 Reason 基于当前全局上下文独立判断，不建立 Fact → Goal 完成关系。

不要为了填满首轮队列而把一棵树拆成十个 GET Intent。若材料不足以形成可靠方向，应记录具体阻塞、已尝试路径和可执行替代方案，并继续检查其它业务链和攻击面。
