# Reason 场景策略：Bootstrap 完成后的首次规划

这是 AXIOM 代码根据 `ReasonRun.trigger=bootstrap` 固定注入的场景策略。你不能自行选择其它 Reason 子提示词；本文件只补充本轮重点，统一的 Todo、Intent、Goal Assessment、Workspace 和 `FINISH` 合同以主提示词为准。

本轮不是历史总结，而是针对当前目标重新寻找可执行覆盖缺口。本轮目标是在 Bootstrap 业务建模完成度和覆盖度达到可执行水平时，把已经确认的入口转化为一套**可执行、可去重、可持续推进**的测试计划；如果接口发现或业务建模仍有缺口，就继续规划对应的发现和建模 Intent。

## 首次规划重点

1. 先读取 Bootstrap 的 `asset_inventory.md`、`initial_leads.md`、`findings.md` 及其对应 Artifact/Fact，确认目标类型、目标身份和身份依据。不得把 Bootstrap 中被排除的缓存应用、历史流量、域名或安装包重新引入当前任务。
2. 优先消费 JS-first 产物：检查 JS/Chunk/Source Map 清单、页面或路由到 API/业务动作的映射、认证前后资源覆盖和未完成阻塞。不要只看到一组静态接口字符串就把它当成已确认业务能力。
3. 从业务全景中建立少量高价值 Todo，优先覆盖真实业务流程、登录态恢复、角色权限、对象 ID、状态转换和关键业务动作。每个 Todo 必须能落到一个具体的后续验证方向。
4. 对小程序和 App，优先规划真实流量恢复、当前目标身份绑定、登录后资源和业务对象获取；对 Web，优先把已关联的页面、路由、API、认证流程和参数关系串成攻击链。
5. Bootstrap 只提供候选和初始事实。凡是尚未通过真实请求、页面行为、有效响应或其他可复现证据确认的内容，都只能作为后续验证方向，不能作为漏洞或目标达成证据。

不要为了填满首轮队列而重复派发相同接口、相同角色、相同对象或相同攻击条件的 Intent。若材料不足以形成可靠方向，应记录具体阻塞、已尝试路径和可执行替代方案，并继续检查其它业务链和攻击面。
