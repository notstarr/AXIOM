# Bootstrap 子提示词：App

本文件只补充 Android／iOS App 目标的引导工作流。阶段边界、Scope、技能、三个产物和 `FINISH` 协议仍以主 `bootstrap.md` 为准。

## 唯一目标绑定

先锁定单一 App 身份，优先使用包名或 Bundle ID，并补充名称、平台、版本、安装包哈希、下载来源或安装实例作为证据。只有名称相似、设备上存在某个 App 或目录中发现某个 APK/IPA，不足以证明它就是当前目标。

设备上的其它 App、其它安装包、模拟器历史目录和无关联代理流量不得并入当前任务。无法确认包名、Bundle ID、安装包或目标实例时，只记录身份阻塞，不选择最相似应用代替。

## 首轮发现顺序

1. 确认平台、名称、包名/Bundle ID、版本、安装包或安装实例，记录证据来源。
2. 在已提供且已确认的 APK/IPA 或应用材料中整理权限、导出组件、Activity/Service/Receiver/Provider、URL Scheme、Universal Link/Deep Link、WebView 配置、证书和安全配置。
3. 提取当前包内明确引用的域名、API、页面、参数、第三方 SDK、本地存储、配置文件和可能的凭证位置；区分业务后端、第三方服务和纯静态字符串。
4. 如果当前阶段具备代理流量能力，优先通过真实 App 请求确认 Host、路径、方法、认证、对象 ID 和业务流程。无法绑定到当前包名、进程、会话或操作步骤的历史流量不得归入目标。
5. 记录登录、注册、设备绑定、分享、上传、支付、订单、申诉、投诉、审批等实际出现的入口和后续验证条件，但不在 Bootstrap 深挖完整攻击链。

## 证据边界

- 静态包中的 URL、Secret 形态字符串、组件声明和配置项首先是资产或待验证线索，不自动构成漏洞。
- 只有能够通过包内调用链、运行时行为、真实请求、可访问组件或等价证据确认的内容，才能升级为已验证发现。
- App 内嵌 WebView 仍属于当前 App；只有能通过包内配置、Deep Link、页面操作或真实会话关联时，Web 资产才可纳入当前任务。

## 三个产物的 App 细节

- `asset_inventory.md`：记录平台、名称、包名/Bundle ID、版本、安装包/实例、组件、权限、Deep Link、WebView、存储、证书、关联 Host/API 和证据索引。
- `initial_leads.md`：记录待验证组件、静态端点、真实流量恢复、身份/对象/角色边界和业务流程方向，并标明验证所需条件。
- `findings.md`：只记录已经通过运行时、真实请求、可访问组件或其它充分证据确认的漏洞；单纯静态字符串、权限声明和理论配置风险不得写入。

三个文件必须使用主提示词规定的“目标类型／当前目标身份／身份判断依据”头部，其中目标类型填写 `App`。
