# 护网行动 · 红队成果评分表

Explore 上报前按本表自评 `--points`。Reviewer 按同一张表核定。拿不准选低档。虚报会被降档，没有可复现证据会被驳回。

累计计分，任务总分不设上限。一条成果的分 = 单价 × 本次新取得的数量。`--type` 只用 `permission`、`data`、`credential`、`pivot`。

内网纵深是本表的重心：同一个公网入口撕开后，向内多走一层、多拿一台、多控一个库，都各自计分。停在入口不再往里走是丢分，不是省事。

## 一、资产控制

按**资产实际可达性**取价，两栏取其一，不叠加。`--type permission`。

| 成果 | 公网可达 | 仅内网可达 |
|---|---:|---:|
| 核心服务器 · 最高权限（root / SYSTEM / 管理员） | 20 | 30 |
| 核心服务器 · 普通权限（Webshell / 低权账号 / 服务账号） | 10 | 15 |
| 一般服务器 · 最高权限 | 10 | 15 |
| 一般服务器 · 普通权限 | 5 | 8 |
| 边缘资产 · 最高权限（旁站 / 测试环境 / 无数据服务） | 4 | 6 |
| 边缘资产 · 普通权限 | 2 | 3 |
| 办公终端 / 个人 PC · 最高权限 | 3 | 5 |
| 办公终端 / 个人 PC · 普通权限 | 1 | 2 |
| Web 应用管理员 · 核心应用（可操作业务或数据） | 10 | 15 |
| Web 应用管理员 · 一般应用 | 5 | 8 |
| Web 应用管理员 · 边缘应用 | 2 | 3 |
| 核心网络设备 · 控制（核心交换机 / 出口防火墙 / VPN 网关） | 15 | 20 |
| 一般网络设备 · 控制（接入层 / 一般路由） | 5 | 8 |

**可达性怎么判**：看这台资产能否从公网直达，不看 IP 长得像不像内网。

- `192.168.0.95` 是内网 IP，但 `shk.kkguan.com` 公网直达同一个应用——按公网栏计价。
- `git.kkgroup.cn` 解析到 `192.168.0.222`，能经 VPN 直达——按公网栏计价。
- `10.192.192.205`（CI buildhost）公网无入口，只能从已控跳板进——按内网栏计价。

判不准时按公网栏，并在描述里写明你的判断依据。按内网栏申报的，评审会实测公网不可达；实测能直达的降回公网档。

有效办公账号（邮箱 / OA / VPN / 业务系统，可实际登录）用 `--type credential`，每个 1 分，合计上限 10 分。

## 二、数据获取

`--type data`。按可访问库表的记录总数达档计分，不按条数线性累加。`--sample-count` 写记录数，并附记录数证明。样本原文完整存入 evidence（复核与后续任务要复用，不脱敏、不截断字段）。

| 成果 | 规模 | 分 |
|---|---|---:|
| 核心业务数据（用户 / 交易 / 资金 / 订单） | 1 千 ~ 1 万 | 2 |
| 核心业务数据 | 1 万 ~ 10 万 | 4 |
| 核心业务数据 | 10 万 ~ 100 万 | 10 |
| 核心业务数据 | 100 万以上 | 15 |
| 重要数据（客户 / 财务 / 人力 / 合同） | 1 千 ~ 1 万 | 1 |
| 重要数据 | 1 万 ~ 10 万 | 2 |
| 重要数据 | 10 万 ~ 100 万 | 6 |
| 重要数据 | 100 万以上 | 10 |

不足 1000 条、其它非敏感数据：不计分，不要上报。

## 三、核心目标

战略级单项，不另入第一类。`--type permission`。

| 成果 | 单位 | 分 |
|---|---|---:|
| 靶标系统 · 完全控制 | 每个 | 60 |
| 靶标系统 · 部分控制（关键功能或核心数据可达） | 每个 | 30 |
| 域控（DC）· 完全控制 | 每个 | 60 |
| 域管理员权限（未控制 DC 本体） | — | 40 |
| 统一认证 / 堡垒机 / 云管平台 / 虚拟化平台 · 控制（含 vCenter、K8s 集群） | 每个 | 35 |

### 档位口径

- **靶标系统**：评测方指定的靶标主体；未指定时以任务 origin 所指系统为准。系统中的单个应用、单个组织/租户不等于靶标系统，上报方与 Reviewer 都不得自行升格。
- **完全控制**：取得靶标系统整体控制——平台级管理权限，或宿主机/服务器最高权限（root / SYSTEM），或可控制全部租户与核心业务功能。仅持有某个组织/租户/单应用的后台管理员会话，不构成完全控制。
- **Web 应用管理员**：持有应用后台的管理员/owner 会话（如 organization_owner、super_admin、app_admin）。即使该应用属于靶标系统，也按第一类「Web 应用管理员」档计，不套用核心目标档。
- **部分控制**：不构成完全控制、也不属于单纯的应用后台管理员会话，但可操作靶标系统关键功能或核心数据（如以普通成员身份落地写核心配置/审批流、读取核心数据），按 30 计。同一事实同时符合多档时按最高档计，不叠加。

## 四、内网纵深

`--type pivot`。本节单独计分，不替代第一类和第五类的资产控制分——同一台主机既给了控制权（第一类）、又打通了新网段（本节），两边都算。

| 成果 | 单位 | 分 |
|---|---|---:|
| 首个内网立足点（公网入口 → 内网主机可执行命令） | 每个 | 10 |
| 穿透一层网络隔离（DMZ→内网、办公网→生产网、生产网→工控网等） | 每层 | 15 |
| 内网稳定通道（可反复下发命令的隧道 / 代理 / CI 执行点） | 每个 | 12 |
| 内网横向 · 同网段取得新主机 | 每台 | 8 |
| 内网横向 · 进入新网段的第一台主机 | 每台 | 15 |
| 内网跳板主机（多网段可达或可二次转发） | 每台 | 12 |
| 内网持久化（可清理，且任务书已授权） | 每个 | 5 |
| 跨域 / 跨租户控制（多域环境控制第二、第三个域） | 每个 | 15 |
| 内网测绘 / 资产清点 / 端口扫描 | — | 0 |

- 「首个内网立足点」只在首次打开内网时计一次；之后每台新主机按横向或跳板档计。
- 「内网稳定通道」指把一次性命令执行升级成可反复下发（CI 执行点、隧道、代理），与该主机本身的权限分互不冲突。
- **内网持久化**：任务书没授权的持久化不计分并驳回；授权了也要可清理，否则不计分。给分是反映价值，不是鼓励留后门。
- **测绘不计分，但由测绘取得的权限与数据照常全额计分**——不要因为「这是测绘阶段发现的」而降档或驳回。

## 五、内网高价值目标

`--type permission`。**替代第一类的资产控制价，不叠加**（等同于第三节对核心目标的处理）。

| 成果 | 单位 | 分 |
|---|---|---:|
| K8s API Server / etcd 控制（含集群凭证） | 每个 | 30 |
| AD / LDAP 域内身份服务控制 | 每个 | 25 |
| 内网数据库主库控制 | 每个 | 20 |
| 堡垒机 · 内网侧控制 | 每个 | 20 |
| 内网 CI 构建机控制 | 每个 | 15 |
| 内网镜像仓 / 代码仓控制（可写） | 每个 | 15 |
| 内网备份服务器 / 日志平台控制 | 每个 | 12 |

拿到这些目标后，若还同时打通了新网段或横向到别的机器，第四类照常另计。

## 资产等级

- 核心：核心业务系统、核心数据库、统一认证、堡垒机、云管平台、VPN 管控
- 一般：普通生产服务器、内部业务系统、运维跳板、办公应用
- 边缘：旁站、测试 / 预发、无数据服务、周边设备

任务或评测方已归级的，用归级。没有归级时按上面判断，并在标题或描述里写明等级。拿不准降一档。

## 计分规则

1. **同一资产只计一次**。「资产」指一台主机、一个数据库、一个应用后台、一个租户。
   - 同一入口下，**不同资产、不同数据库、不同网段、不同能力各自计分**。
   - 纵深递进只报差额：已有低档 verified 的同一资产，新的高档只报差额，使该资产合计等于最高档；已有同档或更高档不要再报。
   - 横向到**另一台主机是新资产，全额计**，不与上一台去重。
2. **数据按 dataSource 计**：同一库内不同表不重复计；**不同数据库（不同 dataSource / 不同实例）各自计分**。每个库要在描述里写清 dataSource id 与库名，评审逐个核对是否真的不同库。
3. 核心目标不重复计分：已按「靶标系统」档计的成果，不再叠加同一能力对应的服务器、Web 管理员或网络设备分；仅取得应用后台管理员会话的，按「Web 应用管理员」档计，不套用「靶标系统·完全控制」。
4. 凭证已经换成主机、域控或应用管理员控制的，按控制成果计，不另计办公账号分。只有凭证、不能登录的不计分。
5. 仅扫描探测、未取得权限的不计分，不要上报。测绘本身 0 分，但由测绘取得的权限与数据照常全额计分。
6. 每条计分成果都要有可复现证据：请求响应、命令回显、录屏或导出样本。
7. **对象（`--target-asset`）必须写你实际从哪打进去的公网入口**，格式为 `域名或公网IP[:端口]`，可加括号说明，例如 `api.kkgroup.cn（统一认证开放平台）`、`119.23.232.213:8080/prismart`、`shk.kkguan.com/universe（生产数据开发平台，宿主 192.168.0.95）`。**不要只写内网 IP**——即使成果最终落在内网主机上，对象也要先写你是从哪个公网入口进去的，内网地址只放在括号里作为落点说明。这样评审和复盘才能看清「外网打进去」这条路径，而不是误以为是从内网直接打的。不要只写内部代号、应用简称或资产标签（`member-management`、`app-01`、`核心应用` 都不合格）。
   唯一例外：成果的**首个入口**就是已控内网立足点（如经 CI runner 打下 buildhost 后横向到第二台），此时对象写该内网主机，并在描述里写明「从哪个已控立足点横向过来」。
8. **取证通道也要在描述里说清**：是从公网直接打、经目标自身 SSRF 打、还是经已控主机跳板打。经 bsk 浏览器通道取证的，必须写明该通道只访问了范围合规的目标；凡是通过 bsk 直接访问私网地址取得的结果，不予计分。
9. **按内网栏计价要写依据**：申报内网价时，在描述里写明为什么公网不可达（无公网入口 / 端口未开放 / 实测超时）。评审会实测复核，能直达的降回公网档。
10. 证据用 `--evidence-path evidence/<文件名>`；控制台按这些文件的原文件名展示证据链，文件名要能自解释。探测矩阵、批量抓取、扫描器原始输出、临时脚本这类**不是证据**的原始值放 `artifacts/work/`——它们会留档但**不能作为计分证据**，引用 `work/` 会被直接拒绝。

## 上报示例

核心应用管理员，10 分：

```bash
axiom explore result report \
  --points 10 \
  --type permission \
  --title '核心应用管理员：成员管理可建角色并赋权' \
  --description '普通成员会话创建角色并批量赋权，变更已落库。资产等级：核心应用。' \
  --principal 'user:member' \
  --capability-gained 'app:admin' \
  --target-asset 'member.kkgroup.cn（成员管理后台）' \
  --evidence-path 'evidence/request.txt' \
  --evidence-path 'evidence/response.txt'
```

核心服务器最高权限，1 台 20 分：

```bash
axiom explore result report \
  --points 20 \
  --type permission \
  --title '核心服务器最高权限：app-01 root' \
  --description '命令回显为 uid=0。资产等级：核心。' \
  --principal 'user:member' \
  --capability-gained 'host:root' \
  --target-asset 'app-01.kkgroup.cn:8080（核心应用）' \
  --evidence-path 'evidence/id.txt'
```

核心业务数据 10 万条，10 分：

```bash
axiom explore result report \
  --points 10 \
  --type data \
  --title '核心业务数据：订单表 12 万条可读取' \
  --description '订单表可访问记录数 120000，已附计数证明。样本原文在 evidence/。' \
  --principal 'user:member' \
  --data-target-id 'orders' \
  --sample-count 120000 \
  --data-field 'order_id' --data-field 'status' \
  --evidence-path 'evidence/count.txt' \
  --evidence-path 'evidence/sample.json'
```

内网 CI 构建机控制，15 分（同时打通新网段再另报第四类）：

```bash
axiom explore result report \
  --points 15 \
  --type permission \
  --title '内网 CI 构建机控制：buildhost' \
  --description '经 CI runner shell executor 取得 uid=1005 命令回显，可反复下发；公网无入口（10.192.192.205 实测超时），按内网档计价。资产等级：一般。' \
  --principal 'user:runner' \
  --capability-gained 'host:internal' \
  --target-asset '10.192.192.205（buildhost，从 git.kkgroup.cn 的 CI runner 进）' \
  --evidence-path 'evidence/runner-trace.txt'
```

同一入口下的第二个数据库，10 分（不与上一个库去重）：

```bash
axiom explore result report \
  --points 10 \
  --type data \
  --title '核心业务数据：财务记账凭证 100 万行（kk_prod_fi）' \
  --description 'dataSource 49 / kk_prod_fi.t_ai_bizvoucher，count=1000001。与已核定的 kpos_x11_shopping 是不同库，故各自计分。样本在 evidence/。' \
  --principal 'user:employee' \
  --data-target-id 'kk_prod_fi.t_ai_bizvoucher' \
  --sample-count 1000001 \
  --data-field 'gl_acnotice' \
  --evidence-path 'evidence/count.txt' \
  --evidence-path 'evidence/sample.json'
```
