# 红队成果审核

审核对象是红队成果。先读 `redteam-scoring`，按那张表核定 `points_awarded`。不以自评分为准。

## 每个报文一张图（必须）

上报的复现步骤是**参考**：照它自己复现一遍即可，报文不必与上报逐字相同。一步里有几个报文
就要几张图——一个请求配一张回包截图，缺一张都会挡住裁决。

```bash
axiom replay shot --task-id t_231 --result x007 --step 2 \
  --output step-02-a.png --caption "步骤 2 报文 1 回包"
axiom review evidence attach --step 2 --kind packet --file step-02-a.png
```

`--step` 必须落在该成果复现步骤的 1..N 之内（越界会被拒，报错里有真实步数）。
**一张图挂在第几步，就只证明第几步**——不要用第 1 步的图去补第 4 步。

`--result/--step` 只是省去手写报文；想自己构造请求就直接传 `--packet-file`，或者用
`axiom replay send`（返回 10 分钟内有效的渲染地址）。`--compare` 才比对「与上报是否一致」，
默认不比对：复核的是结论，不是逐字重放。

业务效果图（后台列表、数据内容、shell 回显）用 `--kind business`，是**可选**的：
它让报告好读，但不计入闸门，也别指望它能顶替报文图。

## 审查

1. 证据要能复现声明的控制、数据或穿透。只有扫描、接口存在、未取得权限 → 驳回。**但测绘本身 0 分不等于成果 0 分**：由测绘取得的权限与数据，按实际取得的资产照常全额核定，不要用「这是测绘阶段发现的」降档。
2. 对照评分表核定。单价 × 本次新取得的数量。拿不准降档。
3. **同一资产只计一次**。已有低档 verified 时，核定分 = 高档 − 已核定低档。已有同档或更高档 → `duplicate`，0 分。
   - 判「重复」前先确认是不是**同一资产**：同一入口下不同主机、不同数据库、不同网段、不同能力，都是新成果，各自核定。
   - **横向到另一台主机不是重复**，全额核。同一资产只是权限档次提升（普通→最高）才走差额。
   - **数据按 dataSource 判重**：同一库内不同表不重复；**不同数据库（不同 dataSource / 实例）各自核定**。核对描述里的 dataSource id 与库名，确认真的是不同库。
4. 核心目标（靶标、域控、域管、统一认证、堡垒机、云管、虚拟化）不另入资产控制类。
5. 有效办公账号每个 1 分，已核定合计达到 10 分后，超出部分核 0。
6. 数据要有记录数证明。不足 1000 条或非敏感数据核 0 并驳回。样本不得出现明文敏感值。
7. 越出任务 Scope 的成果驳回。
8. **对象必须是公网入口。** `target_asset` 只写内网 IP（如 `192.168.0.95`、`10.192.192.205`）时，先确认成果实际是从哪个公网入口打进去的（如 `shk.kkguan.com/universe`、`git.kkgroup.cn`），把对象改成公网入口。落点在内网主机是正常的——只要入口是公网、且路径是「公网漏洞 → 立足点 → 内网」，就按正常成果核定，不要因为出现内网 IP 就当作违规打内网而驳回。例外：首个入口就是已控内网立足点（横向、跳板类），对象写该内网主机，在理由里写明从哪个立足点过来。
9. **只有这几种情形才算违规打内网**：①经 bsk 浏览器直接访问私网地址；②没有任何已确认漏洞或既存立足点，就把内网地址当目标直接打。两种情况都驳回。经目标自身 SSRF、已控主机/CI runner、或公网应用漏洞落到内网的，不算违规。
10. **内网档要实测复核。** 申报按「仅内网可达」计价时，自己验证一次公网是否真打不到（解析 + 连通性探测）。**实测能直达的降回公网档**，并在理由里写明实测结果。反过来，公网确实打不到的就按内网档核，不要因为「看着像内网 IP」或「没有公网域名」而降档。
    - 反例：`192.168.0.95` 有 `shk.kkguan.com` 公网直达 → 公网档；`git.kkgroup.cn` 经 VPN 可达 → 公网档。
    - 正例：`10.192.192.205` 公网无入口 → 内网档。

## 裁决

命令只认这四个词：`verified`、`duplicate`、`ignored`、`needs-human`。

- `verified`：必须给 `--points`。落库以核定分为准。
- `duplicate`：0 分。**这条成立、只是撞了同一条已经计过分的成果**，按「同一资产只计一次」不重复给分。
- `ignored`：0 分。**这条不成立**——证据不足、没取得权限、结论错了。
- `needs-human`：0 分。拿不准，交给人工。

`duplicate` 和 `ignored` 不要再混用：前者是「真漏洞但重复」，后者是「不算数」。判重就写 `duplicate`，别用 `ignored` 冒充——报表要靠这两个状态区分「不成立」和「成立但已计过」。

重复目标用 `--duplicate-of` 指定（填另一条成果的编号，如 `x006`）；说不清撞的是哪条时可以省略，在理由里写明即可。

## 示例

核心应用管理员，核定 10 分：

```bash
axiom review decision submit verified \
  --reason '普通成员会话创建角色并批量赋权，变更已落库。核心应用管理员，10 分。' \
  --points 10
```

核心服务器最高权限，核定 20 分：

```bash
axiom review decision submit verified \
  --reason '命令回显 uid=0，目标是核心服务器 app-01。最高权限 20 分。未另计 Web 管理员。' \
  --points 20
```

同一资产已有低档，只核差额：

```bash
axiom review decision submit verified \
  --reason 'app-01 已核定普通权限 10 分。本次证明 root，最高权限 20 分，差额 10 分。' \
  --points 10
```

证据不足：

```bash
axiom review decision submit ignored \
  --reason '只有接口存在性，没有成功取得权限或数据的可复现证据。'
```

与另一条成果重复（成立，但同一资产只计一次）：

```bash
axiom review decision submit duplicate \
  --duplicate-of x006 \
  --reason '与 x006 为同一事实的重复上报：同一改 username=admin 绕过全部节点鉴权，本条只计一次。'
```

重复：

```bash
axiom review decision submit duplicate \
  --reason '与 x003 为同一资产 app-01 的同档控制，按最高档只计一次。'
```

同一入口、不同数据库，各自核定（不是重复）：

```bash
axiom review decision submit verified \
  --reason 'dataSource 49 / kk_prod_fi.t_ai_bizvoucher，count=1000001。已核定的 kpos_x11_shopping 是另一个 dataSource，不同库，故各自计分。按「重要数据·财务 100 万以上」核 5 分。' \
  --points 5
```

> 数据档单价已于 2026-10-26 统一下调为原表一半（向上取整）：核心 2/4/10/15 → 1/2/5/8，重要 1/2/6/10 → 1/1/3/5。资产控制、核心目标、内网纵深、内网高价值目标四类单价不变。

内网档实测复核：

```bash
axiom review decision submit verified \
  --reason '10.192.192.205 公网实测无入口（curl 超时、无解析），按「内网可达·一般服务器普通权限」8 分核定；且经 CI runner 稳定下发命令，另核「内网稳定通道」12 分，合计 20 分。'
  --points 20
```
