## 1. 本次已解决的核心 Bug（已验证生效）

### 现象
`t_171` 的 Reason 阶段（`rr000976`、`rr000977` 等）反复「释放/死亡，啥事没做」，前端一直显示 Reason 扫描动画但无新 Intent 落库。有的 ReasonRun 重试了 **16 次 Workspace** 仍无产出。

### 真实根因（不是模型试错，不是 FINISH 格式问题）
`reason_workspaces` 的 `commit` 端点每次返回 **HTTP 500**，Traceback 为：

```
psycopg.errors.UniqueViolation: duplicate key value violates unique constraint "pk_intents"
DETAIL:  Key (task_id, id)=(t_171, i068) already exists.
```

**机制**：
- `id_counters` 表 `(t_171, intent)` 的 `next_value` 卡在 **68**，但 `intents` 表实际最大 id 是 **i071**（无空洞）。
- 每次 commit：计数器 68→69，分配出 `i068` → 撞已存在的 `i068` → 唯一约束报错 → **整事务回滚（计数器跟着滚回 68）** → 500 → 工作区 abandon → 无状态重试 → **下一轮又分配 i068** → 无限死循环。
- 这就是为什么「一个坑里摔 16 次」：计数器永远停在 68，不可能自愈。

### 修复（已提交 `9b845d0`）
1. **DB 校正**：`id_counters (t_171, intent)` 由 68 → **72**（= max(i071)+1）。
2. **代码加固（治本）**：`src/axiom/modules/reason/service.py` 新增 `_align_intent_counter()`，在 commit 事务内、分配 intent id 之前执行 `next_value = GREATEST(next_value, max(intent_id)+1)`，使每次 commit 自愈合，未来再发生回滚也不会死循环。
3. 重启 serve + runner 生效。

### 验证结果（2026-08-18 02:49 UTC）
- `rr000977` → `completed`；`rw_001267` → `committed`
- 成功落库 **7 个新 Intent：i072–i078**（部分已 `running` 被 explore 消费）
- `id_counters (t_171, intent)` 已自动推进到 **79**，不再错位

### 顺带全局核查
- 全 41 个任务中**仅 `t_171` 的 intent 计数器曾错位**，其余均正常。
- `t_171` 其他 kind 计数器（fact=75、todo=9、vulnerability=3）均与实际 max 对齐，无需修。
