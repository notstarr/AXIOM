# AXIOM Worker 能力管理与真实工具目录

## 结论

Worker 页面现在明确分成两个互不覆盖的配置面：

~~~text
能力管理 | 后端配置
~~~

- **能力管理**只管理 Bootstrap、Reason、Explore 三个逻辑 Worker 可以获得的 Skill、MCP Tool 和扩展 Tool。
- **后端配置**只管理具体模型执行后端的模型、Base URL、API Key、上下文窗口、思考模式、并发、优先级和阶段后端池。
- 能力写入 phase_capability_bindings；后端配置写入 workers。两者不会通过同一表单互相改写。

## 四类能力的真实边界

### 1. 内置 Tool：固定且只读

内置 Tool 由代码注册表定义，不写入绑定表，也没有启停按钮。API、Worker 页面、工具页面和新 Lease
快照读取同一个注册表。

Pi 原生 Tool：

| Tool | Bootstrap Execute | Bootstrap Conclude | Reason | Explore |
|---|---:|---:|---:|---:|
| read | 是 | 是 | Execute/Conclude | Execute/Conclude |
| write | 是 | 是 | Execute/Conclude | Execute/Conclude |
| edit | 是 | 是 | Execute/Conclude | Execute/Conclude |
| bash | 是 | **否** | Execute/Conclude | Execute/Conclude |

通用 AXIOM 内部操作：

- axiom skill path
- axiom skill doctor
- axiom credential list/get/refresh

Reason 固定操作：

- axiom reason status
- axiom reason todo add/update
- axiom reason intent propose
- axiom reason goal assess

Explore 固定操作：

- axiom explore vulnerability report

AXIOM 内部操作通过阶段环境、活动 Lease 和 HTTP API 校验边界；它们不是 Pi Extension 注册名，因此不会
伪装进入 Pi 的 --tools。Bootstrap Conclude 没有 Bash，阶段 Prompt 和追加 System Prompt 都明确复用
执行阶段已经读取的 whatisvul/SKILL.md，不再要求调用不可用的 Skill CLI。

### 2. Skill：可分配

Skill 继续是方法论与脚本目录，并支持：

~~~text
common / bootstrap / reason / explore
~~~

新 Lease 只通过 --skill 和 AXIOM_SKILL_DIRECTORIES 暴露通用与当前阶段专属 Skill。
whatisvul 是锁定的 common Skill，不能停用、删除或取消 common。

### 3. MCP Tool：可分配

MCP 以具体 mcp_tools.id 分配，而不是整台 Server。选择一个 Tool 时只启动其所属 Server，只注册该 Tool
的稳定运行名，同 Server 其它 Tool 不会披露给模型。

### 4. 扩展 Tool：可分配

“扩展 Tool”是 axiom_tool API/数据库类型的用户界面名称，指受版本控制的 Pi Extension 工具包。框架仍
保留目录扫描、清单、Schema、版本、哈希、风险标签、阶段分配、加载校验和审计，但系统不再附带虚构的
样例能力。

2026 年 8 月 3 日提交中临时加入的以下五个包已经退休：

~~~text
search_text
find_files
list_directory
http_request
run_python
~~~

外部安全命令（如 curl、nmap、nuclei、sqlmap、python）和 Skill 自带脚本继续作为 Bash 或对应 Skill
的执行依赖，不拆成无法真正隔离的假 Tool。

## Worker 页面

能力管理固定展示三个逻辑 Worker 卡片。点击卡片后打开右侧能力抽屉，可在同一处查看和修改：

- 内置 Tool：系统锁定，只读显示调用方式和 Execute/Conclude 可用范围；
- Skill；
- MCP Tool；
- 扩展 Tool。

抽屉直接显示 Bootstrap、Reason、Explore 三列，不把 `common` 暴露成额外操作步骤。三阶段全选会自动
保存为 `common`；取消任一阶段会自动转成剩余阶段的显式绑定。所有修改先进入草稿，确认时只发送一次
矩阵保存。MCP Tool 按 Server 折叠和批量选择，但底层仍保存具体 Tool ID。

Skill、MCP、工具独立页面继续存在，但只管理资源本身并只读显示阶段徽章；能力绑定的唯一编辑入口是
Worker 抽屉。资源页面可通过精确深链打开对应阶段、Tab 和能力。

后端配置模式保留阶段后端池和具体模型后端编辑器。保存模型 API 配置不会修改 Skill、MCP Tool 或扩展
Tool 绑定；修改能力也不会重写模型后端配置。

集中管理的交互、深链和草稿规则详见
[2026-08-04-Agent中心式Worker能力管理](2026-08-04-Agent中心式Worker能力管理.md)。

## API 与 Lease 快照

GET /api/v1/phase-capabilities 在原有 scopes/items 外增加只读 builtin_tools。任何把 builtin_tool
当作可分配能力写入的请求都会被拒绝。

新 Lease 的 phase-capabilities.json 升级为 schema 2：

~~~text
builtin_tools
skills
mcp_tools
mcp_servers
axiom_tools
~~~

schema 1 的既有 Lease 快照仍可读取；旧 Lease 不热修改。Pi --tools 只包含阶段固定的 Pi 原生 Tool、
本 Lease 选中的 MCP Tool 和扩展 Tool。AXIOM 内部 CLI 操作仍由 Bash 与 Lease API 校验提供。
