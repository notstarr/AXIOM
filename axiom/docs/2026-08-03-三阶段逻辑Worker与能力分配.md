# AXIOM 三阶段逻辑 Worker 与能力分配

> **版本说明（2026-08-04）**：本文保留 Reviewer 引入前的三阶段设计与实现事实。当前代码已扩展为 Bootstrap、Reason、Explore、Reviewer 四个逻辑 Worker，增量规则见《Reviewer 第四阶段与漏洞审核状态机》。


## 结论

AXIOM 只定义三个逻辑 Worker：

- Bootstrap Worker
- Reason Worker
- Explore Worker

数据库中的 `workers` 记录不是第四类 Worker，而是**模型执行后端**。同一后端可以进入多个阶段
后端池，后端的模型、Base URL、Key、上下文窗口、思考模式、并发和优先级仍独立保存。

阶段领取使用：

```text
阶段后端池 ∩ Task worker_pool ∩ 已启用 ∩ 非冷却 ∩ 有并发容量
```

后端最大并发跨阶段共享；已领取的 Lease 不因配置修改而热切换。

Worker 概览中的运行量分两层：逻辑阶段卡片的 `running` 只统计该阶段，模型后端的
`shared_running` 统计跨 Bootstrap/Reason/Explore 的总占用；`available` 始终按共享并发计算，避免同一
后端被多个阶段重复计数。

## 能力边界

能力分为四类，但只有后三类进入分配矩阵：

1. **Pi 原生 Tool**：`read/write/edit/bash`，由 Bootstrap/Reason/Explore 阶段合同固定，不在页面分配。
2. **Skill**：方法论和脚本目录，按阶段筛选后通过 `--skill` 注入。
3. **MCP Tool**：以具体 `mcp_tools.id` 绑定，不以 Server 为绑定单位。
4. **扩展 Tool**：版本化目录中的 Pi Extension 工具包，API/数据库类型名仍为 `axiom_tool`。

后三类都支持四个 scope：

```text
common / bootstrap / reason / explore
```

阶段实际能力为：

```text
common 能力 ∪ 当前阶段专属能力
```

通用能力不能单阶段排除。若能力只应给一个或两个阶段使用，先取消 common，再显式勾选目标阶段。
`whatisvul` 是强制启用、不可取消 common 的通用 Skill；历史状态文件若曾将它停用，API 首次启动
会自动修复为启用。

新 Skill 和新扩展 Tool 默认不绑定任何阶段。全局停用、资源缺失或 Server 未 ready 时，旧绑定保留
但在当前 Lease 中不生效；恢复资源或重新启用后自动恢复。

## 数据和兼容

迁移 `20260803_0031` 新增：

```text
phase_capability_bindings
- scope
- capability_kind
- capability_key
- created_at / updated_at
```

唯一键是 `(scope, capability_kind, capability_key)`。迁移会：

- 合并旧 `worker_axiom_tool_bindings`；
- 将旧 Worker MCP 配置按后端参与阶段转换为具体 MCP Tool 绑定；
- 保留旧表和旧配置用于只读兼容；
- 通过 API 首次启动幂等地把当时启用的 Skill 放入 common。

旧 Worker 级扩展 Tool/MCP 写接口返回冲突，避免左右两套配置互相覆盖；旧 GET 只返回投影视图。

## Lease 能力快照

每次新 Lease 生成：

```text
phase-capabilities.json
axiom-tools.json（存在扩展 Tool 时）
```

快照包含当前阶段的内置 Tool 目录、Skill 路径/内容哈希、MCP Tool 的运行名/Schema/Server 配置，
以及扩展 Tool 的版本、包哈希、入口和参数 Schema。Worker 运行期间修改绑定不会改变快照。

Pi 启动时：

- `--tools` 只包含阶段固定的 Pi 原生 Tool 和本快照选中的 MCP Tool/扩展 Tool；
- MCP Extension 只注册选中的具体 Tool，Server 在调用时按快照启动，同 Server 兄弟 Tool 不会暴露；
- 扩展 Tool 由统一激活扩展校验注册名和 Schema，不一致时失败为 `axiom_tool_load_failed`；
- Bootstrap/Reason 的 JSON 和 Explore 的 RPC 使用相同的能力快照；
- Explore Conclude 继承 Skill/MCP，但明确不加载扩展 Tool，不是第四阶段 Worker。

## 管理入口

- `/api/v1/worker-phases`：三个逻辑 Worker 的后端池。
- `/api/v1/phase-capabilities`：只读内置 Tool 目录，以及 Skill、MCP Tool、扩展 Tool 的通用/阶段矩阵。
- Worker 页面拆为“能力管理 / 后端配置”；能力管理可直接分配 Skill、MCP Tool、扩展 Tool。
- Skill、MCP、工具页面复用同一绑定服务；内置 Tool 在 Worker/工具页面只读展示。
