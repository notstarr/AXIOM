# 任务概览实时循环与产物深链

## 本次修复范围

本次只修复任务详情概览的前端读取、还原和定位，不改变 Worker、Reason、Explore、数据库或公开 HTTP API。现有 Audit、Graph、Artifact 和 Task 详情接口仍是唯一数据来源。

## 1. Reason / Explore 循环还原

- 一轮定义为一个唯一 `ReasonRun`，不是 Workspace 重试次数，也不是单个 Goal Cycle。
- 同一 `reason_run_id` 的重试、多个 Workspace 和 Lease 会合并到同一轮；即使本轮创建 0 个 Intent，也保留为完整的一轮。
- 首次进入任务时读取最近最多 2000 条 Audit Event，并按时间正序还原；后续使用 `after_id` 游标增量读取，避免只拿到最早的 200 条记录。
- 兼容实际事件名 `reason_run.created/started/released`、`reason.workspace_opened/abandoned`、`reason.committed`，并兼容历史 `reason_workspace.*` 别名。
- 额外识别 `reason_run.lease_expired`，历史循环会保留失败/放弃原因、Worker、开始和结束时间以及 Workspace 尝试次数。
- 当前循环和历史循环都从 ReasonRun 关联的 Intent 集合还原，不再因为还原失败而把任务全部 Intent 误当成一轮。

阶段状态使用真实任务和 Intent 状态：

- 运行中：旋转动画；
- 等待领取：呼吸动画；
- 完成：静态勾选；
- 失败/放弃：静态警告；
- `prefers-reduced-motion` 开启时关闭运动，仅保留颜色和图标语义。

## 2. 当前执行与最近一批 Intent

展示排序固定为：

```text
running/concluding > claimed > pending > completed > failed/cancelled
```

同一状态内按 `created_at DESC、ID DESC` 排序。存在活动 Intent 时最多展示 12 条活动工作；没有活动工作时，选择最近一个真正创建过 Intent 的 ReasonRun，展示该批次的 Intent。最新零 Intent 的 ReasonRun 不会导致页面回退到最早批次；只有无法从历史事件建立关联时才使用按创建时间排序的兼容回退。

## 3. Fact、Leads 与 Artifact 定位

- 概览分别展示最新 3 条 Fact 和最新 3 条 Leads。
- Leads 使用专门的 `explore.leads` 增量查询，避免大量 Evidence 事件把线索挤出首屏；无 Explore Leads 时回退到 Bootstrap 初始线索。
- Fact 通过 `Intent.to_fact_id` 反查生产 Intent；Leads 和 Artifact 直接使用 `intent_id`。页面显示来源 Intent ID 和简短描述。
- Fact 点击按以下顺序定位：描述中明确引用的 Findings Artifact → Bootstrap Findings → 生产 Intent 的 Findings → 生产 Intent 文件夹；没有具体文件时给出明确提示。
- Leads、最近 Artifact 和完整产物列表统一调用 `openArtifactLocation()`，进入 `#/files?task=...&folder=...&artifact=...` 并预览精确文件。
- 归档或不存在的 Artifact 不会静默跳转到其它文件，而是提示当前对象不可用。

Fact、Leads 和 Artifact 的普通文本仍通过 `x-text` 渲染，不把描述当作 HTML 执行。

## 4. 概览统计修正

- 产物总数使用 Task 的 `artifact_count`，不把当前加载的 12 条误当作总数。
- 漏洞读取上限使用现有接口支持的 200 条，等级统计使用 Task 的 `vulnerability_count`。
- Fact 计数排除 `goal` 和 `origin`。
- 静态资源缓存版本更新为 `20260803-overview-loop-v2`，确保浏览器不会继续使用旧的循环还原逻辑。
